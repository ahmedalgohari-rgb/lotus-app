# Minimalist UI

Direct minimalist UI design and simplification for: **$ARGUMENTS**

## What This Skill Does

Apply rigorous minimalist principles to UI — removing everything that doesn't serve the user's goal until what remains is both sufficient and beautiful.

## Minimalism Is Not Emptiness

Good minimalist UI:
- Contains everything the user needs and nothing they don't
- Makes decisions for the user (don't show 10 options when 2 are right)
- Uses negative space as an active design element
- Trusts the user to infer relationships from proximity, not labels

Bad "minimalism":
- Removes things users need (hiding functionality is not minimalism)
- Uses white space without purpose (just spreading things out)
- Removes visual feedback until the UI feels broken

## Simplification Process

### 1. Element Audit

For each element on the screen, ask:
- What task does this serve?
- What happens if we remove it?
- Can it be implied by context rather than shown?
- Is it here because a user needs it, or because a designer/PM put it there?

Remove anything that can't answer question 1 clearly.

### 2. Visual Noise Reduction

**Text**: Cut every word that isn't load-bearing. Labels, tooltips, and microcopy should be the minimum viable information.

**Color**: 2-3 colors maximum. Every additional color requires justification. One accent color for primary action. Everything else: neutrals.

**Icons**: Use only when the icon is universally understood. Label icons when in doubt. Remove decorative icons entirely.

**Lines and borders**: Replace with spatial relationships (proximity and white space) wherever possible.

**Shadows**: One subtle shadow level for elevation hierarchy, or none.

### 3. Hierarchy Without Decoration

Achieve visual hierarchy through:
- Size variation (not color variation for hierarchy)
- Weight (bold vs. regular, not 5 different font sizes)
- Spacing (more space before = more important)
- Position (earlier in reading order = higher priority)

### 4. The Reduction Test

After simplifying, test:
- Can a new user understand what this screen is for in 3 seconds?
- Is the primary action obvious without labels?
- Does anything feel missing?

If something feels missing, it needed to be there — put it back.

## Output

For $ARGUMENTS: element audit with removal recommendations, simplified visual spec (colors, type, spacing), and a before/after comparison of the key screen or component.
