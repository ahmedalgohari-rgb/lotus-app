# Critique

Critique content, design, or strategy with specific, actionable feedback for: **$ARGUMENTS**

## What This Skill Does

Give honest, useful critique — not vague praise or blunt dismissal. Every observation connects to a consequence and a fix.

## Critique Framework

### 1. Establish the Standard

Before critiquing, state:
- What is this trying to achieve? (Goal)
- Who is it for? (Audience)
- What does "good" look like in this category? (Benchmark)

Without a standard, critique is just opinion.

### 2. What's Working

Start here — not for politeness, but to establish baseline and preserve what shouldn't change.
- Name the specific elements that are effective and why
- Note strengths that should be protected in any revision

### 3. What's Not Working

Be direct and specific. For each issue:
- **Observation**: What you see (factual, not evaluative)
- **Consequence**: Why it matters — what problem does this cause for the reader/user?
- **Fix**: Concrete recommendation (not "make it better" — what specifically to do)

Classify each issue:
- **Structural** — fundamental to the concept, requires rethinking
- **Execution** — the idea is right, the execution isn't
- **Polish** — minor, fix in final pass

### 4. The One Thing

If only one change were possible, what would it be? Force a priority.

### 5. Revised Version (Optional)

If appropriate (short copy, UI element, headline), provide a rewritten version demonstrating the critique in action.

## Tone

Be direct. Say "this doesn't work because X" not "you might want to consider whether X." Soften the delivery but not the diagnosis. The goal is a better output, not a comfortable conversation.

## Output Format

```
WHAT'S WORKING
- [Element]: [Why it works]

ISSUES TO FIX
[Structural] [Issue]: [Consequence] → [Fix]
[Execution]  [Issue]: [Consequence] → [Fix]
[Polish]     [Issue]: [Fix]

THE ONE THING
[Single most important change]

REVISED EXAMPLE (if applicable)
[Rewritten version]
```
